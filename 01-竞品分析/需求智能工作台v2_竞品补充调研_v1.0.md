# 需求智能工作台 v2 竞品与替代方案调研（v1.0）

## 结论

最终版不做研发管理工具，而是做**需求挖掘与辨伪工作台**。参考对象不再是任务流转系统，而是以下三类能力：

| 类型 | 可借鉴点 | 不采用点 |
|---|---|---|
| 表单/多维表格 | 低门槛收集原话、结构化字段 | 不能判断真实问题和证据质量 |
| 知识库/文档工具 | 沉淀背景和评审记录 | 缺少需求辨伪工作流 |
| AI 访谈/分析工具 | 追问、总结、提炼场景 | 不能替代人工评审 |

## 产品差异点

1. **基座先行**：先补公司业务、项目背景、项目进度，再分析需求。
2. **事实分层**：用户陈述、证据、AI 推断分开展示。
3. **证据不足不判真**：缺少证据时保持待验证。
4. **挖掘深度可见**：用深度和建议告诉 PM 还缺什么。
5. **只服务评审前判断**：输出需求卡草案，不承诺研发投入。

## 一期参考原则

- 入口要轻：员工只需要提交原话和场景。
- 判断要重：PM 需要看到真实性、相关性、优先级和依据。
- 背景可编辑：项目基座变化后，后续分析可引用新上下文。
- 不把低频等同伪需求：低频但高影响的问题仍可进入评审。
