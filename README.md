# 需求智能工作台 v2 使用说明

## 结论

当前空间只保留 v2 最新版：**基座信息 + 需求挖掘 + 需求辨伪 + 项目提需入口 + 账号管理**。

工作台使用前必须先维护项目基座信息：

- 公司业务
- 项目背景
- 项目进度

这三项缺失时，系统允许保存项目草稿，但会限制需求提交和智能分析，避免脱离业务上下文判断需求真假。

## 当前功能

| 模块 | 作用 |
|---|---|
| 工作概览 | 查看项目数量、基座完整度、待验证需求、已佐证需求 |
| 基座信息 | 新建和编辑公司业务、项目背景、项目进度、业务目标、关键流程、约束 |
| 需求挖掘 | 提交用户原话，还原场景、问题、影响，补充追问和证据 |
| 需求辨伪 | 判断问题真实性、业务相关性、投入优先级和挖掘深度 |
| 需求卡导出 | 导出 Markdown 需求卡草案，未确认内容保留待补充标记 |
| 项目提需入口 | 每个项目生成公开链接和二维码，员工可扫码或复制链接在浏览器提交需求 |
| 账号管理 | PM/管理员维护账号、部门字段、状态和预留角色 |

## 启动方式

PyCharm 保留后端和两个前端验收模式：

| 配置 | 作用 | 地址 |
|---|---|---|
| 后端 FastAPI v2 8012 | 启动后端接口 | http://127.0.0.1:8012/api/healthz |
| Web 前端 v2 5173 Mock验收 | 验收前端 Mock 效果 | http://127.0.0.1:5173 |
| Web 前端 v2 5173 API联调 | 验收真实 API 联调 | http://127.0.0.1:5173 |

启动顺序：

1. 运行 `后端 FastAPI v2 8012`。
2. 打开 `http://127.0.0.1:8012/api/healthz`，确认返回 ok。
3. 运行 `Web 前端 v2 5173`。
4. 打开 `http://127.0.0.1:5173`。

## 使用流程

1. 进入「基座信息」，补齐公司业务、项目背景、项目进度。
2. 进入「需求挖掘」，提交员工原话和发生场景。
3. 在需求详情中补充追问、证据或反证。
4. 点击智能分析，系统给出问题真实性、业务相关性、优先级和挖掘深度。
5. 由人确认评审结论：已入池、暂缓或不采纳。
6. 导出需求卡草案，交给后续研发流程继续处理。
