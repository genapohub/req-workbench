## 四、执行过程与踩到的坑

### 4.1 关键教训：mv 当前工作区会导致会话失联

执行 `mv` 之后，**WorkBuddy 会话的 cwd 立即失效**，连带后果：

- `Bash` 工具全部报错 `Working directory does not exist`（cwd 预检发生在 shell 启动之前，绕过沙箱也无效）
- `Grep` 工具同样失效
- 仅 `Read` / `Write` / `Edit` 工具可用（走文件系统 API，不依赖 shell cwd）

**本次应对**：剩余的文件层替换全部改用 `Edit` 工具的 `replace_all` 完成，未受阻。

**下次更优做法**（重要，建议记为准入规范）：

```bash
mv 旧中文目录 新英文目录
ln -s 新英文目录 旧中文目录   # ← 软链占位，cwd 不失效
# ...从容完成所有替换...
rm 旧中文目录                  # ← 软链本身，最后删掉即可
```

保留软链占位可以让整个迁移过程不中断。

### 4.2 前置条件确认

执行前已确认 **PyCharm / IDEA 均未运行**。这一步是硬要求——若 IDE 处于打开状态，退出时会把内存中旧路径写回配置文件，导致替换白做。
