# 内部客户管理系统 · 分期实施计划 v1.0

> 依据：`02-产品文档/内部客户管理系统_需求清单_v2.0.md`（M1–M13）＋ `03-技术文档/内部客户管理系统_立项决策表_v1.0.md`（一期范围、两个独立入口、4.5–6 周）。
> 工时口径：1 名 AI 全栈，周一至周六工作。
> 两版口径：**A = 通用 AI 编程工具**（原口径）；**B = Kimi Code Max 套餐 + K3 模型 high 思考档**（推断，依据见下方「两版口径的差别」）。

## 总览

| 期 | 模块 | 一句话目标 | 人日 A | 周期 A | 人日 B | 周期 B |
|---|---|---|---|---|---|---|
| 一期 | M13 + M1 + M2 + **M3** | 一个真实项目能从建档走到验收签字，全程留痕 | 25–35 | 4.5–6 周 | 21–29 | 4–5 周 |
| 二期 | M4 + M5 + M6 + M10 | 客户提需求→评估→报价→确认→转合同→续费，闭环 | 20–30 | 3.5–5 周 | 17–25 | 3–4 周 |
| 三期 | M12 + M9 + M7(简化) + M8 | 管理层能看清经营数据，活动与积分跑起来 | 15–25 | 2.5–4 周 | 13–21 | 2–3.5 周 |
| **合计** | 10 个模块 | — | **60–90** | **约 3–4 个月** | **51–75** | **约 2.5–3 个月** |
| 可选 | 客户入口改小程序 | 不在一期，按需追加 | 10–20 | 2–3.5 周 | 8–17 | 1.5–3 周 |

### 两版口径的差别

**能压的部分**（约占总人日 55–65%）：编码、改码、跨文件重构、页面实现、脚本与联调代码。

- K3 的上下文窗口为 1M token（官方文档：Pro 及以上档位解锁），后端 + 内部后台 + 客户入口三个工程可一次装进同一上下文，减少"改了后端忘了同步前端"的返工；
- K3 是 2.8 万亿参数旗舰模型，官方定位为长程编程（long-horizon programming），多文件任务的首次通过率更高，来回返工轮次减少；
- Max 为最高档订阅，新套餐取消了周额度上限、只保留 5 小时滚动限流窗口，长任务被限流打断的次数更少。

这一段按提速 25–35% 折算，落到整体人日约降 15–20%。以上为**【推断】**：项目尚未开工，无任何一行新系统代码，没有对照实测。

**压不动的部分**（约占总人日 35–45%）：

- 需求澄清、业务流程确认、线框图评审——要人拍板，AI 只能出稿不能代决；
- 甲方配合：客户确认任务、提交 UAT 问题、在线签字，都是等人；
- 域名注册与备案 1–2 周，纯外部日历；
- 服务器开通、数据库账号、部署交接，走内部开发排期；
- 联调、内部试用、修缺陷，需要真实项目数据与真实用户；
- 法定节假日。

**对外建议报数**：一期 **4–5 周**（不要把 3.5 周写进承诺），全量 **2.5–3 个月**。

**额度风险**：Max 套餐的具体月度额度、并发上限，官方文档只列了各档位的功能准入，未公布数字（**未验证**）。官方明确 `k3`（1M）的用量约为 `k3-256k` 的两倍；若中途额度用尽，回退到 `k3-256k` 或原通用工具按 A 口径走即可，范围不变，节奏回退 1–2 周。

## 一期：把「项目交付」跑通（A：4.5–6 周 / 25–35 人日｜B：4–5 周 / 21–29 人日）

**目标**：销售签下的一个项目，从建档、签合同、套用实施计划、分派任务、甲方配合、UAT、到验收签字，全部在一个系统里走完。

### 做什么

| 模块 | 本期做 | 本期不做 |
|---|---|---|
| **M13 系统管理**（约 4 人日） | 组织架构、账号、角色权限（销售/实施/财务/管理层/**客户**）、参数配置（预警天数等）、站内消息、操作日志、上线审批 | 短信、企业微信群机器人、报价/合同/充值审批（二期随功能走） |
| **M1 客户管理**（约 5 人日） | 客户档案 + 多联系人、标签分级、状态流转（潜在→签约→服务中→到期→流失）、跟进记录与下次跟进提醒、N 天未跟进标红、查重、合并与转移归属人 | 客户健康度评分（二期随工单/评价补） |
| **M2 合同管理**（约 5 人日） | 合同录入 + 扫描件上传、编号自动生成、金额/期限/付款方式/模块清单、合同状态、收款计划与到账登记、应收台账、续签与变更留痕 | 到期自动提醒（二期随 M6 做提醒引擎） |
| **M3 项目实施交付**（约 13 人日） | ① WBS 模板可配置（阶段/任务类别/任务项/标准工期），新项目一键套用；② 任务管理：双责任人、内部计划时间 + 客户承诺时间分离、前置依赖、5 种状态、Excel 粘贴批量导入；③ 上线前必完清单 + Go-Live 检查（缺一不允许上线，甲乙双确认）；④ 甲方协作任务推送客户入口、超期 1/3/5 天逐级升级、延期原因留痕；⑤ 看板：项目卡片（阶段/进度/逾期数/距上线日）、列表视图、看板视图；⑥ UAT 任务、培训记录、试运行、验收单在线确认或上传签字件；⑦ 项目资料库、项目留言、周报一键复制微信格式 | 甘特图视图（二期，约 3–5 人日） |
| **客户入口（独立 H5）**（约 4 人日） | 微信内打开、手机号授权登录、只看自己项目：进度视图（不暴露内部计划时间）、待办任务确认、UAT 提问题、验收签字、资料上传 | 在线支付（二期随续费）、小程序 |

### 周排期（按 6 周口径；B 口径下第 6 周的联调与试运行压入第 5 周，整体按 5 周执行）

| 周 | 交付 |
|---|---|
| 第 1 周 | 需求确认、线框图、数据模型、技术骨架（登录/权限/菜单） |
| 第 2 周 | M13 系统管理 + M1 客户管理 |
| 第 3 周 | M2 合同管理 + 收款台账（同步启动服务器与双域名备案） |
| 第 4 周 | M3 实施计划模板 + 任务管理（一期最重的一块） |
| 第 5 周 | M3 上线清单 + 甲方协作 + 客户入口 H5 |
| 第 6 周 | UAT/验收流程 + 看板 + 联调、内部试用、修缺陷、部署上线 |

### 完成标志（Demo 能演这 5 步）

1. 新建一个客户，录入合同与收款计划；
2. 一键套用标准实施模板，生成阶段与任务，分派甲方/乙方责任人；
3. 客户在手机上收到待办，确认完成一项任务；
4. 全部"上线前必完"事项打勾后，走上线审批；
5. 客户在线确认验收单，项目转"已交付"，周报一键复制发群。

## 二期：把「需求与续费」跑通（A：3.5–5 周 / 20–30 人日｜B：3–4 周 / 17–25 人日）

**目标**：老客户提新需求，能评估、报价、客户在线确认、转成合同；合同快到期，系统主动提醒并支持在线续费。

### 做什么

| 模块 | 本期做 |
|---|---|
| **M4 需求管理**（约 6 人日） | 客户在独立入口提需求（文字+截图）、需求池、9 状态流转（已提交→受理→评估→报价→排期→开发→待验收→上线→关闭）、评估（人天/价值/优先级）、客户在线确认或驳回、超时提醒、上线后评分；与 M3 打通（UAT 反馈进需求池/工单） |
| **M5 报价**（约 5 人日） | 报价单（明细行：模块/功能点/人天/单价/折扣）、收费标准库（人天单价与模块价目）、状态流转（草稿→已发送→客户确认/拒绝→转合同）、导出 PDF、版本留痕 |
| **M6 到期续费**（约 5 人日） | 到期前 90/60/30/7 天分级提醒到客服/销售/管理层、客户侧续费入口（到期时间、续费方案）、续费订单与收款确认、续费后合同自动延期、到期未续进流失挽回列表 |
| **M10 工单与评价**（约 5 人日） | 统一工单中心（UAT 反馈 + 投诉合并）、投诉默认高优先级、SLA 24 小时响应与超时升级、关闭后强制评价、评价纳入客户健康度 |
| **M13 补充**（约 2 人日） | 审批流（报价折扣、合同、续费）、企业微信群机器人/短信通知、甘特图视图（M3 补） |

### 完成标志

客户提一条需求 → 评估人天 → 出报价单 → 客户手机上确认 → 自动生成合同 → 合同到期前 30 天系统提醒 → 客户在线续费 → 合同自动延期。

## 三期：把「经营数据」跑明白（A：2.5–4 周 / 15–25 人日｜B：2–3.5 周 / 13–21 人日）

**目标**：老板打开报表就能看到客户、项目、收入三类关键数字，不用再问人要 Excel。

### 做什么

| 模块 | 本期做 |
|---|---|
| **M12 统计报表**（约 6 人日） | 客户（新增/流失/到期/续费率、超时未跟进清单）、项目（在研数、按期交付率、平均交付周期、逾期数、甲方原因延期占比、各阶段耗时）、需求（人天、处理时长、满意度）、工单（新增/解决/遗留）、收入（合同额、到账、续费、开发收入） |
| **M9 活动报名**（约 4 人日） | 活动创建（时间/地点/名额/截止/收费）、报名入口 H5、可配置表单、报名审核与签到核销、报名通知与活动前提醒、参与记录关联客户档案 |
| **M7 积分（简化版）**（约 4 人日） | 积分获取（消费返、活动奖励、转介绍奖励）与后台规则配置、积分抵扣开发费/续费、积分流水与变动通知；**不做**预充值余额、实物兑换与发货 |
| **M8 转介绍**（约 3 人日） | 客户专属推荐链接/邀请码、被推荐人签约后按比例奖励积分、关系链与奖励明细；**不做**排行榜 |

### 完成标志

老板能在一个页面看到「本月新增客户、在研项目、按期交付率、到账金额、续费率」；一场活动能从报名到签到核销走完；客户推荐的新客户签约后积分自动到账。

## 分期依赖与开工前提

| 事项 | 说明 |
|---|---|
| 一期是一切的底座 | 客户、合同、项目三张主表定下来，二三期只是往上叠功能，不重构 |
| 二期依赖一期数据 | 需求、报价、续费都要挂在客户与合同上；一期数据不跑真实项目，二期会缺验证场景 |
| 三期依赖二期数据 | 报表要的是真实成交流程的数据，二期没跑通就出不了有意义的数字 |
| 开工前提 | 服务器与两个域名备案（第 3 周前）、历史数据 Excel（第 4 周前）、业务对接人（第 1 周） |
| 变更纪律 | 每期范围锁死，中途新增一律记入下一期，不插队 |
