# 需求智能工作台 v2 · 生产级验收报告 v1.0

> 日期：2026-10-01　范围：`06-项目编码/v2`（FastAPI 后端 + Vue 3 前端）
> 结论先行：**当前不满足生产级（企业内部正式使用）标准，不建议直接投产。**
> 定位：**功能完整、安全基础合格的 MVP 试点版本**；补齐 P0 阻断项（约 1–1.5 人日）+ P1 部署与审计项（约 3–5 人日）后，可投入单团队小范围内部使用；规模化使用需先做存储架构升级。

## 二、P0 阻断项（不修不能投产，4 项）

### P0-1 初始口令硬编码且全账号同密（严重）
- **证据**：`backend/app/seed.py:83-89` 给 admin / product / employee / engineer 播种同一密码 `Workbench2026!`；该密码同时明文出现在 `frontend/src/mocks/handlers.js:54-57`；新用户创建默认密码同为 `Workbench2026!`（`backend/app/routers/users.py:43`）。
- **风险**：任何能拿到代码的人即掌握全部初始口令；admin 全权限，等于系统裸奔。
- **修复**：① 初始密码改为环境变量注入或首次启动随机生成并打印到服务端日志（不入库、不入仓）；② 登录后强制改密流程；③ 新用户默认密码改为随机生成 + 首次登录强制改密。

### P0-2 生产构建打包 Mock 代码与明文演示凭证（严重）
- **证据**：`frontend/src/main.js:10` 静态 `import { startMock } from './mocks/browser'`；`browser.js` 静态引入 `msw/browser` 与 `handlers`；`USE_MOCK = import.meta.env.VITE_USE_MOCK !== 'false'`（main.js:13）默认开启。
- **风险**：`vite build` 会把 MSW 库与全部 mock 数据（含明文密码、演示业务数据）打进生产 bundle；生产部署若忘设 `VITE_USE_MOCK=false`，前端直接跑在假数据上——对内是数据事故，对外是凭证泄露。
- **修复**：mock 模块改动态导入并以构建环境隔离（如 `if (import.meta.env.DEV)` 或独立 mock 入口），确保生产产物零 mock、零演示数据。

### P0-3 无自助改密能力（严重）
- **证据**：全部路由中无"当前用户修改自己密码"的接口；密码只能由管理员经 `users.manage` 重置（`backend/app/routers/users.py`）。
- **风险**：口令泄露后员工无法自救；与 P0-1 叠加后果放大。
- **修复**：新增 `POST /api/auth/change-password`（校验旧密码 + 强度要求 + 改后失效旧会话）。

### P0-4 登录无防爆破（高）
- **证据**：`/api/auth/login`（`backend/app/routers/auth.py:24`）无失败计数、无锁定、无验证码。
- **风险**：内网可无限尝试口令；P0-1 未修前 admin 口令已知，此处是第二道也是最后一道防线。
- **修复**：同账号连续失败 N 次锁定 M 分钟（计数存库或内存），日志记录失败事件。

## 三、P1 重要风险（投产前建议修复）

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| P1-1 | **无审计日志**：状态变更、评审结论、登录、建删账号均无记录 | 全局无 audit 表/日志模块 | 新增审计表（操作者/动作/对象/前后值/时间），关键写操作落审计 |
| P1-2 | **开发模式部署**：`uvicorn --reload --host 127.0.0.1`，无 workers、无守护、无反代、无 HTTPS（Cookie 无 `secure`） | `backend/run_backend.sh:6`、`auth.py:34-37` | 生产：去 `--reload`、Nginx 反代 + HTTPS、systemd 守护、Cookie 加 `secure`；前端 dist 静态托管 |
| P1-3 | **SQLite JSON-blob 存储天花板**：每表仅 (id, body) 两列；登录按用户名全表遍历（`auth.py:17-21`）；读-改-写无事务锁，并发写丢更新；无迁移框架 | `backend/app/database.py:25-45` | 明确容量边界（≤50 用户/数百条需求可用）；规模化前升级正规 schema（或 Postgres）+ 唯一索引 + 乐观锁 |
| P1-4 | **公开表单无防刷**：知 URL 即可无限提交 | `backend/app/routers/public.py:43` | 加 IP 频率限制或提交口令/验证码 |
| P1-5 | **CORS 方法/头全放开**（`*`）且带凭证，仅靠 origin 白名单兜底 | `main.py:19-25` | 收紧 `allow_methods/allow_headers` 到实际集合 |
| P1-6 | **无安全响应头**：无 CSP / X-Content-Type-Options / X-Frame-Options / Referrer-Policy | FastAPI 默认无 | 加安全头中间件（反代层统一加亦可） |
| P1-7 | **校验错误泄露内部结构**：`RequestValidationError` 直接回传 `exc.errors()`，且破坏统一响应包裹 | `main.py:46-48` | 仅回统一文案，细节记日志 |
| P1-8 | **前端无单元测试**，E2E 靠手工 Playwright 脚本 | `frontend/` 无测试配置 | 加 Vitest，优先覆盖 StatusTag / MethodCheckCard 枚举映射、DataTable 密度透传 |

## 四、P2 建议项（可排期）

- SQLite 数据文件未加 `.gitignore`（untracked 但未 ignore，存在误提交风险）——`backend/运行数据/工作台.sqlite3`
- `@app.on_event("startup")` 已 deprecated，改 lifespan 事件——`main.py:28`
- 需求列表无分页，全量返回；过期会话从不清理（表无限增长）
- 备份脚本无定时执行 / 保留策略 / 异地副本——`backend/backup_v2.sh`（仅手动 tar）
- 依赖未做漏洞审计：建议 `pip-audit` + `npm audit` 各跑一轮并纳入 CI
- 前端兜底文案硬编码 `127.0.0.1:5173`——`main.js:88`
- 前端 localStorage 存会话 token（XSS 可读）；建议生产仅靠 HttpOnly Cookie，去掉 Bearer 双通道
- Mock 种子与真实后端种子漂移（前端 24 条 vs 后端 1 条）——验收/演示环境需明确区分，避免误判"数据丢失"

## 五、已达标的生产级要点（保留）

1. 密码 scrypt 加盐哈希（n=16384）+ `secrets.compare_digest` 防时序攻击——`deps.py:12-24`
2. 会话 token 强随机（`secrets.token_hex(24)`）、7 天过期、Cookie HttpOnly + SameSite=Lax、登出即删会话——`deps.py:27-31`、`auth.py`
3. 服务端强制 RBAC：接口级 `require_perm` / `role_permissions`，前端菜单仅做展示层——`deps.py:61-70`
4. 员工数据隔离：`visible_requirements` / `get_requirement_for_user` 服务端过滤，仅见本人需求——`analysis.py:87-108`
5. SQL 全参数化，表名固定白名单，无注入面——`database.py`
6. CORS origin 白名单（非 `*`）——`main.py:15-25`
7. Pydantic 入参校验 + Literal 枚举约束状态/评分域——`schemas.py`
8. 统一响应包裹与错误处理（AppError/HTTPException/校验错误三分支）——`main.py:34-48`、`resp.py`
9. 后端测试 17 项全过：权限、基座拦截、辨伪不自动拒绝、导出范围、员工隔离、账号 CRUD——`backend/tests/`
10. 数据备份脚本（tar + SHA256 校验）——`backup_v2.sh`
11. 前端渲染无 `v-html`，Vue 插值默认转义，XSS 面小
12. 公开表单仅暴露必要字段且走基座完整性校验——`public.py`
