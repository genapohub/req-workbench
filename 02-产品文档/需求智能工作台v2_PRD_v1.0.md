# 需求智能工作台 v2 PRD（v1.0）

## 1. 产品定位

面向公司内部员工、产品经理和技术评估人，把员工的模糊诉求还原成有业务上下文、有证据、有判断依据的需求卡。

一句话定位：**先补齐业务基座，再挖真实场景，最后辨别需求真假。**

## 2. 核心目标

| 目标 | 说明 |
|---|---|
| 还原真实问题 | 不把用户说的方案直接当需求 |
| 建立判断基座 | 公司业务、项目背景、项目进度必须可编辑、可引用 |
| 区分事实和推断 | 用户陈述、证据、反证、AI 推断分开展示 |
| 支撑人工评审 | 输出可评审、可追溯的需求卡草案 |

## 3. 用户角色

| 角色 | 主要操作 |
|---|---|
| 普通员工 | 提交原话、补充追问、查看自己的需求 |
| 需求负责人 | 维护基座信息、补证据、智能分析、评审判断、导出需求卡 |
| 技术评估人 | 查看需求，补充技术风险和成本建议 |
| 管理员 | 使用内置管理账号查看全部功能 |

## 4. 功能范围

### 4.1 工作概览

展示项目数、基座完整项目数、待验证需求数、已佐证需求数，以及真实性和优先级分布。

### 4.2 基座信息

每个项目维护以下字段：

| 字段 | 要求 | 用途 |
|---|---|---|
| 公司业务 | 核心字段 | 判断需求是否贴合公司业务链路 |
| 项目背景 | 核心字段 | 判断当前阶段、目标用户和项目边界 |
| 项目进度 | 核心字段 | 判断当前是否适合投入 |
| 业务目标 | 建议填写 | 关联需求价值 |
| 关键流程 | 建议填写 | 定位卡点环节 |
| 约束条件 | 建议填写 | 辅助判断风险和成本 |

核心字段缺失时，项目可保存，但需求提交和智能分析会提示先补齐。

### 4.3 需求挖掘

员工提交：所属项目、标题、用户原话、发生场景、真实问题、影响说明。

需求详情展示：

- 判断总览：真实性、业务相关性、优先级、挖掘深度
- 基座引用：公司业务、项目背景、项目进度
- 真实场景还原：原话、场景、问题、影响
- 证据与疑点：支持证据、反证、缺失信息
- 深挖建议：下一步追问和验证动作
- 时间线：提交、追问、证据、分析、状态变化

### 4.4 需求辨伪

| 维度 | 取值 | 规则 |
|---|---|---|
| 问题真实性 | 待验证 / 已佐证 / 存在反证 | 由证据和反证决定 |
| 业务相关性 | 待明确 / 直接相关 / 间接相关 | 基于基座信息判断 |
| 投入优先级 | 待评估 / 高 / 中 / 低 | 基于四维评分和证据充分度 |
| 挖掘深度 | 0-5 | 场景、问题、影响、证据、方案完整度 |

证据不足时保持待验证，不生成已佐证结论。

### 4.5 导出需求卡

导出 Markdown 需求卡草案，包含：基座信息、用户原话、真实问题、判断结论、证据、候选方案、深挖建议、评审记录。

## 5. 主流程

```text
维护基座信息
  ↓
提交用户原话
  ↓
补充追问和证据
  ↓
智能分析与深挖建议
  ↓
人工确认真实性、相关性、优先级
  ↓
导出需求卡草案
```

## 6. 验收标准

- 登录后只显示工作概览、基座信息、需求挖掘。
- 项目支持编辑公司业务、项目背景、项目进度。
- 基座缺失时阻止需求提交和智能分析。
- 缺证据时保持待验证。
- 有支持证据时可判定已佐证。
- 有反证时可判定存在反证。
- 低频但高影响的问题不被自动否定。
- 导出内容只包含需求挖掘与辨伪相关信息。


## 9. 2026-09-30 新需求补充

### 9.1 项目二维码和公开提需表单

每个项目在「基座信息」列表中提供公开提需入口：**复制链接、查看二维码**（2026-10-01 起移除「打开」按钮——它与复制链接重复且无独立价值；员工侧入口统一为「扫码」或「复制链接后在浏览器打开」）。员工无需理解后台字段，可通过手机微信扫码或复制链接在 PC 浏览器打开 `/submit/{projectId}`，页面自动回显项目名称，并填写标题、用户原话、最近一次真实场景、当前卡点、影响说明、姓名和部门。公开表单提交后进入需求池草稿状态，由 PM 继续补证据、追问和评审。

### 9.2 方法论优先于 AI

需求分析不再突出“AI 自动判断”，而是展示四类方法论检查：

| 方法 | 判断内容 | 未满足时处理 |
|---|---|---|
| JTBD 场景 | 是否说明谁在什么场景要完成什么任务 | 标记缺真实场景 |
| 5 Whys | 是否至少经过一轮为什么追问 | 提示继续追问真实目标 |
| 证据链 | 是否有数据、工单、截图或访谈摘录 | 保持待验证，不判真需求 |
| RICE 四维 | 是否填写影响范围、问题强度、业务价值、实现成本 | 不生成综合优先级 |

AI 只负责整理、提示和辅助分析；真实性、优先级、入池结论仍由人确认。

### 9.3 账号管理

新增「账号管理」菜单，一期支持账号新增、编辑、删除、启停、部门字段和角色选择。默认账号仍保留 PM 可登录能力，角色、菜单、权限模型作为扩展字段存在，但本期不做完整角色权限配置后台。
