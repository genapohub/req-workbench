# 需求智能工作台 v2 设计方向（v1.0）

## 1. 设计目标

让 PM 进入页面后能快速回答四个问题：

1. 这个项目的业务基座是否完整？
2. 这条需求是不是有真实证据？
3. 是否挖到了真实场景和真实问题？
4. 当前是否值得进入人工评审？

## 2. 页面重点

| 页面 | 设计重点 |
|---|---|
| 工作概览 | 基座完整度、待验证、已佐证 |
| 基座信息 | 公司业务、项目背景、项目进度缺项提示 |
| 需求挖掘 | 原话、场景、真实性、相关性、深度、优先级 |
| 需求详情 | 判断总览、基座引用、真实场景、证据疑点、深挖建议 |

## 3. 交互原则

- 页面先展示结论，再展示依据。
- 基座缺失必须醒目提示。
- 证据不足时不使用积极结论。
- 按钮不堆叠，详情抽屉只保留挖掘、分析、评审和导出动作。
- 列表页先给筛选与密度控制，再给数据（数据量上来后不必改造结构）。
- 操作路径收短：行内高频操作平铺，低频/终态操作放底栏或更多菜单。

## 4. 视觉体系（2026-10-01 升级至 v3.0）

基准从「飞书式浅色」切换为 **Spotify 式深色沉浸**：近黑底（#121212）+ 单一功能绿强调（#1ed760）+ 胶囊几何 + 重阴影 + 紧凑字阶。

- **为什么换**：深色沉浸让数据表格、状态标签与占比条成为画面主角，符合本产品「看数据、做判断」的定位；同时深色在长时间评审场景下更省眼。
- **怎么落地**：只重写 `tokens.css` 的取值（变量名不变），组件与页面结构零改动；浅色值保留在 `[data-theme="light"]`，可随时切回。
- **本地化取舍**：按钮「全大写 + 宽字距」是拉丁字母规则，中文界面改为 0.02em 微字距、不做大写；表格内文字按钮保持小圆角，避免密集列表出现一排药丸。
