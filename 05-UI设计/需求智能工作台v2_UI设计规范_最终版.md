## 1. 设计目标与交互原则

让 PM 进入页面后能快速回答四个问题：基座是否完整？需求是否有真实证据？是否挖到真实场景和问题？当前判断是否值得进入人工评审？

- 页面先展示结论，再展示依据和操作；信息密度适中，不做营销化视觉。
- 基座缺失必须醒目提示（warning 提示条，不隐藏），并拦截需求提交与智能分析。
- 证据不足时不使用积极结论；待验证/待明确用中性色，不制造已确认感。
- 按钮不堆叠：行内高频操作平铺，低频/终态操作放底栏或更多菜单；详情抽屉保留挖掘、分析、评审、导出动作。
- 空状态要告诉用户下一步做什么；所有危险或最终判断动作需要明确理由。

## 2. 视觉体系（Design Tokens v3.0）

| 项 | 规范 |
|---|---|
| 氛围 | 专业、克制、可信；近黑沉浸，让数据成为主角 |
| 强调色 | 功能绿 `#1ed760`（仅主操作/激活态/关键强调，绿底配黑字 `#121212`） |
| 页面背景 | `#121212`（Level 0）；卡片/侧栏/顶栏 `#181818`，次级面板/表头 `#1f1f1f`，浮层 `#252525` |
| 正文 | `#ffffff`；次级文字 `#b3b3b3`；边框 `#2a2a2a` |
| 几何 | 按钮/搜索框 999px 胶囊，卡片 8px，品牌标与头像 50% 圆 |
| 阴影 | 0.30–0.50 重阴影（深色上轻阴影不可见） |
| 字阶 | 页标题 20/700，区块标题 16/600，正文 14/400，辅助 12/400（靠字重而非字号拉开层级） |

语义状态色（深底 14% 透明底 + 亮色字）：`#1ed760` 已佐证/已满足/启用；`#ffa42b` 待补充/澄清中/缺项；`#f3727f` 存在反证/不采纳；`#539df5` 待评审/间接相关；`#b3b3b3` 待验证/待明确/草稿。

- **换肤机制**：只改 `tokens.css` 取值、不改变量名 → 组件零改动；浅色值保留在 `[data-theme="light"]` 骨架，给 `<html>` 加属性即可切回。
- **本地化取舍**：按钮全大写+宽字距只适用拉丁字母，中文界面保留 0.02em 微字距、不做大写；表格内文字按钮保持小圆角。
- 动效：`cubic-bezier(.4,0,.2,1)`，120/200/280ms，禁弹跳/回弹；适配 `prefers-reduced-motion`；焦点环满足 WCAG AA，触控目标 ≥44px。

### 视觉红线（违反即打回）

1. 禁 emoji 图标；2. 禁紫粉渐变；3. 禁「渐变+发光+毛玻璃」三件套；4. 颜色/字号/间距/圆角/阴影一律取 Token，禁止硬编码（EP teleport 组件统一在 `overrides.css` 覆盖）；5. 强调绿只做功能色不铺底；6. 深色底禁止 ≤0.15 轻阴影；7. 红色只留给「存在反证/不采纳」，不用于高优先级。

## 3. 组件规范（11 个公共组件）

事实源：`frontend/src/components/*.vue`。硬约束：组件/页面内禁止硬编码流浪数值，禁止绕过枚举自写 label/颜色。

| 分类 | 组件 | 职责 |
|---|---|---|
| 布局 | `AppSidebar` | 左侧导航 224px（自绘非 el-menu），桌面折叠 64px（状态记忆 localStorage），<768px 转滑入抽屉+遮罩，子路径高亮 |
| 布局 | `AppTopbar` | 顶栏 56px：折叠开关 + 面包屑（首页/当前页）+ 用户菜单（退出为二级操作） |
| 容器 | `PageHeader` | 统一页头：标题/描述/右侧操作区 |
| 容器 | `PanelCard` | 统一卡片容器，`flush` 容纳表格与工具条（与 `.wb-panel` 工具类二选一不混用） |
| 容器 | `DataTable` | 覆写 EP 表格 CSS 变量，密度切换（large/default/small），内置统一空状态；列显隐需 `:key` 强制重建 |
| 容器 | `FormDialog` | 统一表单弹窗，loading 锁 ESC、disabled 禁提交（基座不完整时提交需求 disabled） |
| 内容 | `StatCard` | 指标卡，骨架屏 loading、数字色调 tone、等宽数字 |
| 内容 | `EmptyState` | 统一空状态，sm（表格内）/md（页面级），action 引导 |
| 内容 | `SectionTitle` | 分区标题（左短竖条），替代 el-divider |
| 内容 | `MethodCheckCard` | 方法论检查卡，只呈现「是否通过」，status 只传 `ok`/`missing`，绝不把规则结果渲染成事实结论 |
| 原子 | `StatusTag` | 自绘状态标签（EP 无 neutral 态），所有状态标签统一走它，不用 el-tag 自定义色 |

表格工具条用 `.wb-table-toolbar` 工具类；抽屉底栏用 `.wb-drawer-footer`。

### 统一枚举（`constants/enums.js`）

| 枚举 | key → label（tone） |
|---|---|
| `AUTHENTICITY` | pending 待验证(neutral) / supported 已佐证(success) / contradicted 存在反证(danger) |
| `RELEVANCE` | unknown 待明确(neutral) / direct 直接相关(success) / indirect 间接相关(warning) |
| `PRIORITY` | unassessed 待评估(neutral) / high 高(warning) / medium 中(info) / low 低(neutral) |
| `STATUS` | draft 草稿(neutral) / clarifying 澄清中(warning) / review 待评审(info) / pooled 已入池(success) / deferred 暂缓(neutral) / rejected 不采纳(danger) |
| `ACCOUNT_STATUS` | active 启用(success) / disabled 停用(neutral) |
| `BASE_STATUS` | complete 已完整(success) / incomplete 缺项(warning) |
| `METHOD_STATUS` | ok 已满足(success) / missing 待补充(warning) |

**数据契约陷阱（改后端前必读）**：① `method_cards` 的 status 是 `ok`/`missing`，不是 pass/fail，写错全部退化成灰色；② `/api/dashboard` 的 `by_status` 键是中文 label（用 `toneByLabel` 反查），`by_authenticity`/`by_priority` 是英文 key；③ 后端 `analysis.py` 或 mock 改方法论卡名时，`constants/methodology.js` 的 key 必须同步。

### 状态覆盖

每个页面/组件覆盖 default/hover/focus/active/disabled + loading/error/empty/success 共 9 态；StatCard/DataTable 内置 loading/empty，FormDialog 内置 loading/disabled，页面级 error/success 由各 view 补齐（6 个 view 已落实）。

## 4. 页面设计契约

### 4.0 全局布局

左侧导航 224px（折叠 64px），菜单按角色下发：工作概览、需求挖掘、基座信息、账号管理；顶栏 56px（折叠开关+面包屑+用户菜单）；主内容区内边距 20px、最大宽 1280px；<768px 侧边栏转抽屉+遮罩，路由跳转自动收起；页面切换 120ms 淡入（尊重 reduced-motion）。

### 4.1 登录页 `/login`

左侧品牌区主文案「先补齐业务基座，再判断需求真假」（近黑 + 一束绿色微光）；登录卡片仅账号/密码/登录按钮（不展示演示账号，无预填）；成功进入 `/overview`。

### 4.2 工作概览 `/overview`

指标卡 ×4（项目数/基座完整项目/待验证需求/已佐证需求，带语义图标）；下方评审状态、真实性、优先级分布（数字 + 占比条，色调随语义）；基座不完整时顶部 warning 提示条。

### 4.3 基座信息 `/projects`

工具条：关键词搜索（项目名/公司业务/背景/进度）+ 实时条数。表格列：项目、基座完整度、公司业务、项目背景、项目进度、需求数、提需入口（复制链接、二维码；「打开」入口已于 2026-10-01 移除）、操作。编辑弹窗字段：项目名/公司业务/项目背景/项目进度/业务目标/关键流程/目标用户/限制条件；缺项允许保存，黄色标签展示缺失字段；二维码生成失败时提示手动复制链接。

### 4.4 需求挖掘 `/requirements`

三视图 Tab 顺序「看板 / 需求池 / 列表」，默认看板：

| 视图 | 排版形态 |
|---|---|
| 看板 | 按状态分列卡片墙（6 列带计数）；卡片=标题+原话(2 行截断)+项目名/深度+真实性/优先级标签；点击开详情抽屉 |
| 需求池 | 表格 + 按优先级排序（高→中→低→待评估，同级按深度降序） |
| 列表 | 全量表格 + 工具条（关键词搜索、项目/真实性/优先级/状态四筛选、重置带计数、实时条数、列设置 7 列显隐、密度切换三档） |

看板视图下隐藏状态筛选与列设置/密度（列即状态，避免语义冲突）。筛选/密度/列显隐为会话内状态（刷新回默认，未持久化）。提交按钮在无完整基座项目时禁用。**不做看板拖拽改状态**（状态变更属评审判断，须人在抽屉里确认）。

### 4.5 需求详情抽屉（`/requirements?req={id}`，宽 560px）

分区顺序（按阅读逻辑：结论→事实→判定→行动）：

1. 使用流程引导（折叠面板：还原现场→方法论检查→按建议补料→人工拍板 + 术语速查）
2. 判断总览：真实性、业务相关性、优先级、挖掘深度（进度条）
3. 基座引用：公司业务、项目背景、项目进度
4. 基座背书：同项目已入池需求 Top3（重合词/疑似同类标记），无命中显示空态
5. 真实场景还原：原话、场景、还原问题、影响说明
6. 证据与疑点：支持证据、反证、缺失信息
7. 方法论检查：JTBD/5Whys/证据链/RICE 四卡（带白话注释，「运行方法论检查」按钮在区块标题 extra）
8. 深挖建议：独立区块（「生成追问建议」按钮在 extra）
9. 评审判断：状态、真实性、优先级
10. 时间线：提交、追问、证据、分析、状态

操作行：编辑需求 / 补充证据 / 补充追问（各开 FormDialog，必填校验 + 提交中 loading）。底栏固定：关闭 + 导出需求卡 Markdown。

### 4.6 账号管理 `/users`

工具条：搜索 + 状态下拉 + 总数；账号列表、新增、编辑、删除、启停、角色选择、部门字段；禁止删除当前登录账号。

### 4.7 公开提需表单 `/submit/:projectId`（公开页）

回显项目名称；字段：标题、用户原话（必填）、最近一次真实场景、当前卡点、影响说明、姓名、部门；状态覆盖 loading / 缺基座禁用 / 提交成功 / 提交失败；深色主题（`#121212` 白字）。

## 5. 走查结论（2026-10-01 复检，全部通过）

菜单与角色下发、基座编辑与缺项提示、需求列表判断列、详情抽屉分区、旧入口清理、移动端适配（<768px 抽屉+遮罩）、侧边栏折叠与记忆、面包屑、筛选工具条、密度切换、列设置、抽屉底栏、深色对比度亮度审计（无浅色残留底、无深底深字）、「打开」入口零残留。

**遗留待办**：① 筛选/密度/列显隐未持久化（建议记 URL 参数）；② 前端无单元测试框架（未装 Vitest，靠后端 pytest + build + Playwright 冒烟兜底）；③ `MethodCheckCard` props 注释过期（写 pass/warn/fail，实际 ok/missing），待清理注释；④ 评审判断下拉对全员可见（后端按权限强制鉴权），角色隔离细化待确认。
