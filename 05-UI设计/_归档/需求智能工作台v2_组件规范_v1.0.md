# 需求智能工作台 v2 组件规范（v1.0）

> 本文档是 **UI 组件层** 的唯一事实源，沉淀自 2026-09-30 的「UIUX 升级 + 全量组件化」改造。
> 与《页面设计契约》《design-tokens》《UIUX 走查报告》《设计方向》配套使用，互不重复：本文档只讲「有哪些组件、怎么用、枚举与 Token 怎么对齐」，不重复讲视觉方向与走查结论。

## 1. 组件总览（11 个）

按职责分四类。改造前页面内 `toolbar` / `page-head` 等私有样式已全部清除，统一走下列组件。

| 分类 | 组件 | 一句话职责 |
|---|---|---|
| 布局 | `AppSidebar` | 左侧导航（自绘，非 el-menu），深色实底，支持折叠态与子路径高亮 |
| 布局 | `AppTopbar` | 顶栏（56px 深色实底）：折叠开关 + 面包屑 + 用户菜单（退出降为二级） |
| 容器 | `PageHeader` | 统一页头：标题 / 描述 / 右侧操作区 |
| 容器 | `PanelCard` | 统一卡片容器，支持 `flush` 容纳表格与工具条 |
| 容器 | `DataTable` | 覆写 EP 表格 CSS 变量统一风格，支持密度切换，内置统一空状态 |
| 容器 | `FormDialog` | 统一表单弹窗，loading 锁 ESC / disabled 禁用提交 |
| 内容 | `StatCard` | 指标卡，含骨架屏 loading 态、数字色调 |
| 内容 | `EmptyState` | 统一空状态，含教育引导 action slot |
| 内容 | `SectionTitle` | 分区标题（左侧短竖条），替代 el-divider |
| 内容 | `MethodCheckCard` | 方法论检查卡片（PRD 9.2），只呈现「是否通过」 |
| 原子 | `StatusTag` | 自绘状态标签，支持 `neutral` 态与状态圆点（EP 无 neutral） |

| prop | 类型 | 默认 | 说明 |

- Slot：`icon`

#### EmptyState
| prop | 类型 | 默认 | 说明 |
|---|---|---|---|

| `size` | `sm|md` | `md` | `sm` 用于表格内，`md` 用于页面级 |

#### SectionTitle
| prop | 类型 | 默认 | 说明 |
|---|---|---|---|
| `text` | `String` | `''` | 分区标题 |

- Slot：`default`（覆盖 text）、`extra`（右侧补充）。
- 替代 el-divider，左侧短竖条 + `--wb-fs-lg` 标题。

#### MethodCheckCard
| prop | 类型 | 默认 | 说明 |
|---|---|---|---|
| `name` | `String` | **必填** | 方法论名称，如「JTBD 场景」 |
| `text` | `String` | `''` | 检查说明 |
| `status` | `ok|missing` | `''` | 检查结果（**传枚举 key，见 §4**） |

- Slot：`default`
- Emit：无
- ⚠️ **关键对齐**：`status` 必须传 `METHOD_STATUS` 的 key（`ok` / `missing`），组件内部经 `labelOf(METHOD_STATUS, ...)` / `toneOf(METHOD_STATUS, ...)` 渲染「已满足 / 待补充」。
- ⚠️ **已知待对齐**：组件 props 注释里写的「pass 已满足 / warn 待补充 / fail 未满足」是**过期注释**，实际代码已按枚举 `ok`/`missing` 工作。后续清理注释，调用方一律以 `enums.js` 为准。
- 红线：本卡片只呈现「检查是否通过」，**绝不把 AI 结果渲染成事实结论**（契约 §8）。

### 2.4 原子类

#### StatusTag
| prop | 类型 | 默认 | 说明 |
|---|---|---|---|
| `label` | `String` | `''` | 显示文案 |
| `tone` | `success|warning|danger|info|neutral` | `neutral` | 语义色调 |
| `size` | `sm|md` | `sm` | `sm` 表格内 / `md` 抽屉与卡片内 |
| `dot` | `Boolean` | `false` | 是否显示状态圆点 |

- Slot：`default`（覆盖 label）
- 这是自绘组件，核心解决 EP 原生 `el-tag` 无 `neutral` 态的问题；所有状态标签统一走它，不要再用 `el-tag` 自定义颜色。

- 缓动 `--wb-ease: cubic-bezier(.4,0,.2,1)`，时长 120 / 200 / 280ms。**禁弹跳/回弹缓动**。

- 已适配 `prefers-reduced-motion`：系统开启减少动效时全部过渡降级。

## 4. 统一枚举与数据契约约定

> 完整定义见 `enums.js`。**所有状态展示必须走枚举 + `StatusTag`，禁止页面内自写 label/颜色映射。**

### 4.1 枚举字典
| 枚举 | key → label（tone） | 适用 |
|---|---|---|
| `AUTHENTICITY` | pending 待验证(neutral) / supported 已佐证(success) / contradicted 存在反证(danger) | 真实性 |
| `RELEVANCE` | unknown 待明确(neutral) / direct 直接相关(success) / indirect 间接相关(warning) | 相关性 |
| `PRIORITY` | unassessed 待评估(neutral) / high 高(warning) / medium 中(info) / low 低(neutral) | 优先级 |
| `STATUS` | draft 草稿(neutral) / clarifying 澄清中(warning) / review 待评审(info) / pooled 已入池(success) / deferred 暂缓(neutral) / rejected 不采纳(danger) | 需求主状态 |
| `ACCOUNT_STATUS` | active 启用(success) / disabled 停用(neutral) | 账号 |
| `BASE_STATUS` | complete 已完整(success) / incomplete 缺项(warning) | 基座完整度 |
| `METHOD_STATUS` | **ok 已满足(success) / missing 待补充(warning)** | 方法论检查 |

辅助函数：`labelOf(map,key)`、`toneOf(map,key)`、`toneByLabel(map,label)`、`optionsOf(map)`，及预置 `STATUS_OPTIONS` / `AUTHENTICITY_OPTIONS` / `PRIORITY_OPTIONS`（供 `el-option` 与筛选复用）。

### 4.2 ⚠️ 数据契约陷阱（改后端前必读，曾导致线上视觉退化）

**陷阱一：`METHOD_STATUS` 取值不是 PRD 里的 pass/fail。**
- 后端 `backend/app/analysis.py` 的 `build_method_cards` 实际返回 `ok` / `missing`。
- 若按 PRD 写 `pass/fail/warn`，`MethodCheckCard` 经 `toneOf` 查不到 → 全部退化成中性灰，看不出「已满足 / 待补充」。
- 正确：`MethodCheckCard` 的 `status` 只传 `ok` / `missing`。

**陷阱二：`/api/dashboard` 的 `by_status` 键是中文 label，不是英文 key。**
- 后端 `backend/app/routers/overview.py` 用 `{STATUS_LABELS.get(k,k): c}` 输出，键是「澄清中」这类中文。
- 而 `by_authenticity` / `by_priority` 的键是英文 key。
- 若 Dashboard 统一按英文 key 查枚举 → `by_status` 整块退化成灰色。
- 正确：用 `toneByLabel(STATUS, label)` 按中文文案反查色调，`toDistList()` 同时兼容两种键形态。

### 4.3 色调语义红线
- **红色只留给「存在反证 / 不采纳」**，不要拿来表示「高优先级」，避免语义混淆。
- **待验证 / 待明确用中性色**，不制造「已确认」的错觉。

## 5. 视觉红线（全局，违反即打回）

1. 禁 emoji 图标（状态/导航一律用文字或 SVG）。
2. 禁紫粉渐变。
3. 禁「渐变 + 发光 + 毛玻璃」三件套（v3.0 背景为近黑 + 一束绿色微光，不做发光描边，毛玻璃已移除）。
4. 所有颜色取自 Token，禁止页面/组件内硬编码色值（EP teleport 到 body 的部分统一在 `overrides.css` 覆盖）。
5. 强调绿（`#1ed760`）**只做功能色**：主操作 / 激活态 / 关键强调，不用于装饰性铺底。
6. 深色底上禁止轻阴影（≤0.15 的投影在近黑上不可见，一律用 `--wb-shadow-sm/md/lg`）。

## 6. 组件使用规范

1. **PanelCard vs `.wb-panel`**：复杂卡片（有标题/操作/footer）用 `PanelCard`；极轻量静态块可用 `.wb-panel` 工具类。同一张卡片二选一，不混用。
2. **状态标签**：一律 `StatusTag`，不回退 `el-tag` 自定义色。
3. **状态覆盖 9 态**：每个页面/组件须覆盖 default / hover / focus / active / disabled + loading / error / empty / success（契约 §0）。`StatCard` 与 `DataTable` 已内置 loading/empty，`FormDialog` 内置 loading/disabled，其余页面级 error/success 由各 view 自行补齐（已落实于 6 个 view）。
4. **主题**：v3.0（2026-10-01）起**深色为默认主题**（`color-scheme: dark`），浅色值保留在 `[data-theme="light"]` 骨架中；给 `<html>` 加该属性即可切回，组件代码零改动。
   - 换肤方式：只改 `tokens.css` 的取值，**不改名、不改结构**——组件全部走 Token 是这套机制的前提。
   - 深浅切换后需自查对比度：深色上「深底深字」与「浅色残留底」是两类典型事故，可用亮度审计脚本全量扫描（见《UI迭代清单》v3.0 验证记录）。
