# 需求智能工作台 v2 页面设计契约（v1.0）

## 0. 全局布局

- 左侧导航宽 224px（折叠态 64px），菜单：工作概览、需求挖掘、基座信息、账号管理（按角色下发）。
- 顶栏高 56px：左侧为「侧边栏开关 + 面包屑（首页 / 当前页）」，右侧为用户菜单（退出为二级操作）。
- 主内容区内边距 20px，内容最大宽度 1280px。
- 响应式：<768px 侧边栏转为滑入抽屉 + 遮罩，路由跳转自动收起；桌面折叠状态记忆到 localStorage。
- 页面切换有 120ms 淡入过渡（尊重 `prefers-reduced-motion`）。
- 所有页面覆盖 loading、empty、error、success、disabled 五态。

## 1. 登录页 `/login`

- 左侧品牌区主文案：先补齐业务基座，再判断需求真假。
- 登录卡片包含账号、密码、登录按钮。
- 登录成功进入 `/overview`。

## 2. 工作概览 `/overview`

指标卡：

1. 项目数
2. 基座完整项目
3. 待验证需求
4. 已佐证需求

下方展示评审状态、问题真实性和投入优先级分布。存在基座不完整项目时，顶部显示 warning 提示。

## 3. 基座信息 `/projects`

表格列：项目、基座完整度、公司业务、项目背景、项目进度、需求数、**提需入口**（复制链接、二维码）、操作。

- 表格上方为工具条：关键词搜索（项目名 / 公司业务 / 项目背景 / 进度）+ 实时条数。
- ⚠️ 2026-10-01 起**移除了「打开」入口**（原 `openPublicForm` 直接 `window.open`，与复制链接重复且无独立价值）；员工侧进入方式只剩「复制链接后在浏览器打开」与「扫码」两种。

编辑弹窗字段：

- 项目名
- 公司业务
- 项目背景
- 项目进度
- 业务目标
- 关键流程
- 目标用户
- 限制条件

缺项允许保存，但用黄色标签展示缺失字段。

## 4. 需求挖掘 `/requirements`

表格上方为工具条（与表格同容器，浅底 + 下边框分隔）：

- 关键词搜索：标题 / 原话 / 项目名
- 筛选：项目、真实性、优先级、状态（均为纯前端筛选，不改接口）
- 重置按钮带生效筛选项计数
- 右侧：实时条数、**列设置**（7 列可勾选显隐）、**密度切换**（宽松 / 标准 / 紧凑）

表格列（可显隐）：需求原话、项目、问题真实性、业务相关性、挖掘深度、优先级、状态。

提交按钮在没有完整基座项目时禁用。筛选与列显隐为会话内状态（刷新回到默认，未做持久化）。

### 4.1 三个视图的排版（2026-10-01 对齐竞品重构）

| 视图 | 排版形态 | 竞品依据 |
|---|---|---|
| 列表 | 表格（全量） | Jira 表格视图 / 飞书表格视图 |
| 需求池 | **表格 + 按优先级排序**（高→中→低→待评估，同优先级按挖掘深度降序） | Jira backlog 的核心就是「按优先级排序的有序列表」 |
| 看板 | **按状态分列的卡片墙**（6 列：草稿 / 澄清中 / 待评审 / 已入池 / 暂缓 / 不采纳，列头带计数） | Jira Board「列即工作流状态」/ 飞书看板视图「按单选字段分组的卡片墙」 |

- 看板卡片：标题 + 原话（2 行截断）+ 项目名 / 挖掘深度 + 真实性 / 优先级标签；点击卡片打开详情抽屉（与表格行点击一致）。
- 看板视图下**隐藏状态筛选与列设置/密度**（列即状态，表格控件无意义），避免语义冲突。
- ⚠️ **拖拽改状态一期不做**：本产品的状态变更属于「评审判断」，应与真实性、优先级一起在抽屉里由人确认；拖拽易误触改结论，与「AI 不自动改结论」的产品红线冲突。需求强烈时可再加，并需加二次确认。

## 5. 需求详情抽屉

抽屉宽 560px，分区：

1. 判断总览：真实性、业务相关性、优先级、挖掘深度。
2. 方法论检查（PRD 9.2）。
3. 基座引用：公司业务、项目背景、项目进度。
4. 真实场景还原：用户原话、发生场景、还原问题、影响说明。
5. 证据与疑点：运行方法论检查、生成追问建议、证据与反证列表。
6. 评审判断：状态、真实性、优先级。
7. 时间线：提交、追问、证据、分析、状态。

**底栏（固定可见，不随正文滚动）**：关闭 + 导出需求卡 Markdown。原正文底部的「操作」分区已并入底栏。

## 6. 视觉规则

- 问题真实性、业务相关性、优先级都用语义色标签。
- 待验证和待明确用中性色，不制造已确认感。
- 已佐证用绿色，存在反证用红色。
- 挖掘深度用进度条表达。
- 分布类数据（评审状态 / 真实性 / 优先级）除数字外，用**占比条**表达「多少」，颜色随语义色。


## 8. 2026-09-30 页面补充契约

| 页面 | 路由 | 核心交互 | 状态要求 |
|---|---|---|---|
| 项目公开提需表单 | `/submit/:projectId` | 回显项目名称，提交用户原话、场景、卡点、影响、姓名、部门 | loading / 缺基座禁用 / 提交成功 / 提交失败 |
| 账号管理 | `/users` | 账号列表、新增、编辑、删除、启停、角色选择、部门字段 | loading / empty / error / success / disabled |
| 基座信息 | `/projects` | 每行展示复制链接、二维码（**2026-10-01 起移除「打开」**） | 二维码生成失败时提示手动复制链接 |
| 需求详情 | `/requirements?req=id` | 展示方法论检查卡片，运行方法论检查，生成追问建议 | 不把 AI 结果展示为事实结论 |

视觉调整：产品名统一为“需求智能工作台”；退出入口放入用户更多菜单。

## 9. 2026-10-01 视觉体系升级（Design Tokens v3.0）

整体换肤为 **Spotify 式深色沉浸主题**，改的是令牌取值，页面结构与功能零改动。

| 维度 | v2.x（飞书浅色） | v3.0（深色沉浸） |
|---|---|---|
| 页面底色 | 浅绿渐变 `#f4f6f5` | 近黑 `#121212` |
| 卡片 / 侧栏 / 顶栏 | 白 `#ffffff` | `#181818`（浮层 `#252525`、表头 `#1f1f1f`） |
| 主色 | 深绿 `#245647` | 功能绿 `#1ed760`（仅强调 / 主操作 / 激活态） |
| 主按钮 | 绿底白字，6px 圆角 | **绿底黑字，999px 胶囊** |
| 语义色 | 低饱和绿橙红蓝 | `#1ed760` / `#ffa42b` / `#f3727f` / `#539df5`，14% 透明底 + 亮色字 |
| 阴影 | 0.05–0.12 轻投影 | 0.30–0.50 重阴影（深色上轻阴影不可见） |
| 几何 | 小圆角 | 胶囊按钮 + 圆形品牌标 / 头像，卡片 8px |

- 主题可切换：`[data-theme="light"]` 保留浅色骨架，给 `<html>` 加该属性即可切回，组件代码零改动。
- 取舍：Spotify 的「按钮全大写 + 1.4px 字距」只适用于拉丁字母，中文界面保留 0.02em 微字距、不做大写；表格内文字按钮仍用小圆角，避免密集列表出现一排药丸。
