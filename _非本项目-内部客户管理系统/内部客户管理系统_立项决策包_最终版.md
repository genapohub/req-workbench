## 一、立项结论

**准予立项。** 一期做 **2 个端、3.5–4 周**上线，先跑通「客户 → 合同 → 实施交付 → 验收」主线；全量四期 **82–121 人日、约 3.5–4 个月（14–16.5 周）**。

一句话定位：**建典谟自己用的客户与交付管理系统**，管"我们怎么把项目交付给客户"；与典谟对外售卖的 CRM/SCRM 产品不是一回事，不冲突、不替代。

### 端的形态（4 个入口、2 个域名）

| # | 端 | 谁用 | 期次 |
|---|---|---|---|
| 1 | 内部管理后台（电脑网页，独立域名） | 销售、实施顾问、财务、管理层 | **一期** |
| 2 | 客户协作入口（微信内 H5，独立域名、独立登录） | 典谟的客户 | **一期** |
| 3 | 代理商入口（复用客户入口前端按角色出菜单 `/agent`，不新增域名） | 代理商 | 四期 |
| 4 | 管理层大屏（复用后台域名只读页 `/screen`，可配 IP 白名单） | 老板/管理层 | 四期 |

内部移动端 App 不做（手机浏览器可用）；微信小程序不做（客户侧统一微信内 H5）。

## 三、技术选型（可行性结论）

**不能迭代，只能「借壳重建」**：现有 req-workbench 只服务「需求真伪分析」，与 CRM 13 个模块零业务重叠。共享的是前端壳层与工程习惯（约 2,052 行、占前端 39.7%），折算到 CRM 实际工作量 **< 10%**；后端可复用仅约 91 行（deps.py + resp.py）。存储模型是最大障碍：现有 5 张 `(id, body)` JSON 单表无法支撑 CRM 的条件查询与统计，必须换正规 schema。

| 方案 | 结论 |
|---|---|
| **A（推荐）Python 3.12 + Django 5 + DRF + MySQL + 复用 Vue3 壳** | ORM/迁移/Admin/权限/定时任务开箱即用；Django Admin 直接承载 M13/M5/M7/M10 的运营配置 |
| B PHP + Laravel | 可行（前端语言无关），但本机零 PHP 环境、团队无 PHP 维护意愿待确认 |
| C 沿用 FastAPI | 不推荐：迁移/RBAC 数据范围/审计/通知/定时任务/报表全部自建，二期技术债集中爆发 |

复用方式：**白名单 rsync 复制**（不是整仓 cp）：前端 `styles/`、`components/`（删 MethodCheckCard、重写 AppSidebar 菜单）、`App.vue`、`api/`、`store/session.js`、`constants/enums.js`（模式）、`router` 骨架、`package.json`/`vite.config.js`/`index.html`（去 MSW）；后端 deps.py/resp.py 仅作设计参考。明确排除 `.git`、`node_modules`、`dist`、`.venv`、`backend/`、`views/`、`mocks/`、运行数据。新仓库建议命名 `crm-service`（英文目录，与根目录英文化结论一致）。

**现存 7 项规格缺口**（编码前必须补齐，否则反复返工）：无优先级 MVP 边界（已由分期解决）、无验收标准、无数据模型与状态机、无权限矩阵（数据范围/价格隔离）、无历史数据迁移口径、无提醒渠道资质前置（企微主体/短信报备/支付商户号）、需求清单版本号曾自相矛盾（已以 V2.0 定版入库）。

周排期：第 1 周需求确认+线框图+数据模型+技术骨架+M13（同步启动服务器与双域名备案）；第 2 周 M1+M2；第 3 周 M3 模板与任务；第 4 周 M3 收尾+客户入口+联调上线。

完成标志（Demo 5 步）：建档录合同 → 套用模板分派双责任人 → 客户手机确认任务 → 必完清单打勾走上线审批 → 在线验收转已交付、周报一键复制发群。

### 二/三/四期要点

- **二期**：M4 需求池 9 状态流转与客户在线确认；M5 报价单+收费标准库+PDF+版本留痕；M6 到期 90/60/30/7 天分级提醒+续费+合同自动延期；M10 统一工单中心（UAT 反馈+投诉合并）+SLA 24h+强制评价；短信（约 2–3 人日）与电子签章（约 4–6 人日）接入。
- **三期**：M12 六类指标驾驶舱；M9 活动报名到签到核销；M7 积分简化版（获取/抵扣/流水）；M8 转介绍（不做排行榜）。
- **四期**：M11 代理商等级折扣+自助报价+价格隔离；M7 完整版（余额账本不可变流水、实物兑换发货）；微信支付 JSAPI（充值/续费/首款/退款/对账，不做支付宝与外部 H5 支付）；大屏只读页。支付接入前续费充值走「线下转账+后台登记入账」，账本与流程不变，接支付后不做返工。

### 分期依赖

一期是底座（客户/合同/项目三主表定下来，后续只叠不重构）；二期依赖一期真实数据；三期依赖二期成交流程数据；四期挂 M5 价目、M12 口径，不另建算法。变更纪律：每期范围锁死，中途新增记入下一期。

## 六、一期技术验收口径（DoD）

1. 核心表有迁移脚本，可空库一键建起；禁止 JSON 单列存储业务实体。
2. 每个接口有权限校验与数据范围过滤；越权返回统一错误码。
3. 写操作全部落审计日志。
4. 列表接口全部支持分页、排序、条件筛选。
5. 定时任务可在管理端查看执行记录与失败重试。
6. 附件走对象存储抽象，本地可用磁盘实现。
7. 前端关掉 Mock，build 产物不含 `mockServiceWorker.js`。
